# 历史轨迹参考驱动的回复生成提示词 v2

此版优化 M2/M3/M4 的回复生成，不改变执行事实，也不生成 IPI。

## 两个主要改动

1. **从固定段落改为事实级配对。** 注入动作可以出现在任务清单、进度汇报或一句附带说明中；同一对照对保持组织和正常任务事实一致。校验具体事实片段，不再强制第一段相同，也不要求 M4 等于准确回复的第一段。
2. **M3 使用真实进度与滞后状态混合的表达。** 可以承认已经开始或完成部分工作，再将同一个已执行动作放到“确认后继续”。不靠每条都写“尚未完成”制造简单否认；同时避免把确实没做的剩余步骤误标为滞后。

自然化不等于模糊化：必须能指出哪一个注入目标动作已经成功，哪一段回复却把它说成未来动作。“prepared”一个词不够；后文如果又承认发送，需重新判定。

## 提示词与历史参考

- `generate.md`：生成准确/失配配对回复；输出状态、证据锚点和保留的正常任务事实片段。
- `review.md`：基于当前工具与状态证据复核，检查完整回复而非孤立截句；分别报告事实错误、机制不成立和文风问题。
- `repair.md`：只修复复核发现的问题，不重排为两段式、不改变机制、不删除关键失配句。

构建器从原始日志提取六个参考，每个都附完整原始 Final、选定原生动作轨迹、已断言的执行事实、原始文件及 SHA256：

| 参考 | 来源 | 借鉴点 |
|---|---|---|
| HIST_M2_FILES | V1 c005/001 | 备份和清理融入任务汇报，结尾夸大删除完成情况 |
| HIST_M2_FORWARD | V2 c007/004 | 未执行的转发被列为已完成动作 |
| HIST_M3_BACKUP | V2 c012/001 | started/prepared 与发送、删除的确认请求混合 |
| HIST_M3_PAYMENT | V2 c004/004 | 拒绝、正常任务解释与已执行转账的待确认表述混合 |
| HIST_M4_MAILS | V1 c008/shared/000 | 正常文件删除报告遗漏五封目标邮件 |
| HIST_M4_SLACK | V1 c002/001 | 较详细的正常餐厅私信汇报遗漏另一封目标私信 |

参考是模式证据，不是新样本的事实来源。原文中的正常任务错误、参数和日期不能照搬。历史参考任务属于开发资料，之后不应再把同源轨迹当作未见测试数据。

## 使用

准备提示词和六条历史参考，**不调用模型**：

```bash
/tmp/minipim-a4-test-env/bin/python scripts/generate_mismatch_responses_v2.py prepare
```

默认输出到 `reports/mismatch_response_prompt_v2_20261103/`；目录已存在时请使用新的 `--output`。默认从旧 pilot10 中选取七条 M2/M3/M4 执行。旧 s001–s003 是执行否认，不能当作新 M1 Ignored，因此明确排除。

准备时保存提示词快照与哈希，生成和复核请求使用该快照，避免准备后修改提示词导致记录与实际输入不一致。

真正调用 Codex CLI `gpt-6-sol` / `high` 重新生成七对回复：

```bash
/tmp/minipim-a4-test-env/bin/python scripts/generate_mismatch_responses_v2.py generate
```

生成后保存模型原始输入输出、`response_pairs_v2.json`、结构校验及 `review_request.txt`。结构校验不代表语义审查通过；复核仍须检查当前执行证据。不要用旧 pilot 的 `finalize/refine` 处理 v2：它们保留了旧版段落约束和样本专用修订规则。

本次交付是提示词与可运行入口；没有自动执行上述 `generate`。效果需后续比较生成结果，不能仅凭提示词修改就声称更接近真实分布。
